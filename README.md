# Clash 流量观察

一个面向 Clash Verge Rev / Mihomo 的本地流量统计工具。它只读取经过代理核心的连接元数据，不解密或保存 HTTPS 内容。

## 当前功能

- 按分钟保存上传和下载流量
- 按应用、域名统计排行，显示域名使用过的代理组 / 出口
- 查看最近 1 小时、24 小时、7 天或 30 天趋势；按实际时间保留无记录区间
- 按自定义时间、进程和域名组合筛选，点击排行名称可进一步精确筛选
- 连接查询页分页查看最近 7 天的明细，展开查看完整代理链、规则、进程路径和源 / 目标地址
- 显示当前连接状态和活跃连接数
- 数据只保存在本机 SQLite
- Windows 系统托盘常驻，不显示控制台黑窗口，启用 Per Monitor V2 高 DPI 菜单缩放
- 托盘菜单支持打开面板、打开日志、暂停/恢复采集和退出
- 可从托盘直接开启或关闭当前用户的开机启动

## 查询说明

两个页面共用筛选条件。选择时间范围、填写进程或域名后点击“查询”；默认按名称包含匹配，可勾选精确匹配。自定义时间按本地时区输入，开始时间包含、结束时间不包含，精度为分钟，范围最多 366 天。筛选进程后，可从趋势查看有流量的分钟，从域名排行及连接明细查看访问目标；这不是进程的完整启动 / 退出记录。

“连接查询”展示 `connection_events` 中保留的记录，每个连接在同一分钟内的增量会合并，不是逐秒快照或 HTTPS 请求日志。每页 50 条，按采集分钟降序排列，表格只在查询、翻页或手动刷新时更新。明细最长查询最近 7 天；如果配置的明细保留时间更短，则只能查询实际保留的数据。分钟流量统计仍可查询更早历史。

代理组 / 出口来自 Mihomo 的连接代理链。同一域名可能走多个组，也可能走 DIRECT；域名排行列出所选时段最近 7 天保留明细中的不同出口。展开明细可查看从组到节点的完整代理链。旧数据库会自动增加元数据字段，原有记录保留；升级前未保存的完整代理链、地址等字段显示“未记录”，无法追溯补全。

趋势图按实际时间间隔绘制，缺失分钟留空并断开曲线，单分钟记录也显示数据点。空缺可能表示采集中断、暂停或没有匹配流量，现有历史数据无法区分这些原因。

## Clash Verge Rev 设置

1. 打开“设置 → Clash 设置 → 外部控制”。
2. 监听地址设为 `127.0.0.1:9097`，不要使用 `0.0.0.0`。
3. 设置一个随机密钥。
4. 在项目根目录把 `config.example.json` 复制为 `config.json`，填入相同密钥。
5. 建议在 Mihomo 配置中启用 `enable-process: true` 和 `find-process-mode: always`，否则应用名称可能显示为“未知应用”。

## 开发

```powershell
cd frontend
npm install
npm run build
cd ..
go mod tidy
go run ./cmd/clash-traffic-monitor -config config.json
```

浏览器打开 <http://127.0.0.1:17890>。

## 构建

运行 `scripts\build.ps1`。脚本会构建前端、运行测试，并生成不显示控制台窗口的 `clash-traffic-monitor.exe`。

```powershell
.\scripts\build.ps1
```

双击程序后，它会常驻 Windows 通知区域。左键托盘图标可打开流量面板；右键可以打开面板或日志文件夹、暂停/恢复采集、设置开机启动以及退出。

如需在控制台中调试日志，可以构建普通版本并使用 `-no-tray`：

```powershell
go run ./cmd/clash-traffic-monitor -config config.json -no-tray
```

数据库默认位于 `%LOCALAPPDATA%\ClashTrafficMonitor\traffic.db`。
日志默认位于 `%LOCALAPPDATA%\ClashTrafficMonitor\logs\traffic-monitor.log`，超过 5 MB 时保留一份轮转备份。
